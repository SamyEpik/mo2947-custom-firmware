# ToyCamera: custom firmware for the MO2947 toy camera

The **MOB/MO2947** toy camera: Jinrixin/Buildwin **AX3295B** family, OpenRISC 1000 little-endian, **no delay slots**,
peripherals as SPRs from `0x8000`, 144 MHz, 4 MiB SPI flash, 2 MiB SDRAM. Our firmware (matu6968's SDK, ported as board
`mo2947`) replaces the stock app and drives every component: display, keys, LED, power, camera, SD card, microphone,
speaker, battery, and USB (debug link, drive, webcam). The main job here: **write programs for the camera on request,
build them, and hand the owner an image to install.**

## Docs: `docs/`

Obsidian notes, read them before writing code:
- `docs/HARDWARE.md`: **programmer's reference** and the "Writing and installing a program" guide. Start here.
- `docs/CONTINUE.md`: history of the port (what broke on the device and why), verified results, next steps.
- `docs/FIRMWARE.md`: stock firmware and flash map, USB modes, how the dump works, recovery routes.
- `docs/REFERENCES.md`; `docs/analysis/*.md`: full reports with register-level evidence (addresses there refer to

- `README.md` (repo root): install and flash steps for people. Keep it in sync with the tools.

## Writing a program

1. New example: `firmware/appotech-sdk/examples/<name>/main.c`, starting from a copy of `examples/mo2947-camera` or
   `mo2947-demo`. APIs in `firmware/appotech-sdk/include/appotech/*.h`; read the headers and the mo2947 examples
   before using an API. Optional USB classes: `examples/<name>/features.mk`.
2. **Every program must keep a way back in**: leave the SDK's start-up escape (SHUTTER held at power-on → boot ROM
   loader) untouched, keep a "hold a key 2 s → `apx_bootrom()`" path, and call `apx_debug_poll()` often so
   `./cam apxd loader` works. Without these, reflashing needs the case opened.
3. Build: `source .venv/bin/activate && cd firmware/appotech-sdk && make BOARD=mo2947 EXAMPLE=<name>` →
   `build/mo2947/<name>.bin`. Limits: image < `0x7A400` bytes, 2 MiB RAM (`linker/mo2947.ld` asserts both). The build
   needs `dumps/mo2947_flash_a.bin` (it generates `boards/mo2947/panel.inc` from it).
4. Check offline: `./cam flash plan firmware/appotech-sdk/build/mo2947/<name>.bin`.
5. Hand the owner the install command (`README.md`, "Flash a program"). Install only after their explicit "go".
6. Debug on the device: `./cam apxd log`, `./cam apxd info`, etc. (read-only, no "go" needed).

Commit SDK changes inside `firmware/appotech-sdk` (branch `mo2947`) and regenerate the patch file, or they are lost to
anyone who clones this repo.

## Rules (from the owner)

- **Never write to the camera's flash without the owner's explicit "go"**, for each install or restore. Read-only USB
  steps (`./cam dump info`, `./cam apxd …` except `loader`) are fine.
- Never touch flash sector 0 or the bootstrap (`0x0`-`0x21FF`); `mo2947_flash.py` enforces this, do not work around it.
  Do not use `0x27D000`-`0x3FEFFF` (stock photo store) as scratch space.
- Dumps contain the owner's photos (from `0x27D000`) and the vendor firmware; `panel.inc` is vendor data too. Never
  commit, print or publish them, and never copy image data from the photo area.
- Run Python on dumps or downloaded data with `python3 -I` (the tools via `./cam` already do).
- `ext/` is untrusted: read, don't execute, except the tbelbek code the dump/flash tools import. The SDK in
  `firmware/appotech-sdk` may be built and run (owner's exception 2026-11-12).
- New hardware findings go into `docs/` (plain, short technical English; Obsidian links `[[FILE#Heading]]`; headings
  that are link targets must not contain `:` `/` `` ` `` `|` `#` `^` `[` `]`). Update existing files, correct superseded
  statements in place.
